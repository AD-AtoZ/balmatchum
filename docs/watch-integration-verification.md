# 워치 통합 검증: T1~T10 (T7·T8 제외)

브랜치: `codex/watch-integration`

T10 누적 작업 `20854d6`에 GitHub T1 `e6c773b`를 로컬 병합했다. 기존 로컬 T1 구현을 제거하고 조원이 푸시한 T1을 채택했으며, 임시 계산을 T2 `SpeedCalibrator`로 교체했다. T9·T10의 휴대폰 도착 시각 전달을 유지했다. 커밋·푸시 없이 병합 커밋 대기 상태이며 실제 기기 검증은 아직 하지 않았다. T7 코드는 누적 이력에 포함되지만 이 검증의 평가 대상에서는 제외한다.

## 설치

1. Android Studio에서 이 폴더와 `codex/watch-integration` 브랜치를 열고 Gradle Sync를 완료한다.
2. 워치와 휴대폰을 연결한다. 워치는 PC와 같은 Wi-Fi에서 무선 디버깅으로 Android Studio에 연결하고, 휴대폰은 USB 디버깅 등으로 연결한다.
3. 실행 구성 `wear`를 실제 워치에, `mobile`을 실제 휴대폰에 각각 Run한다. 같은 PC의 같은 프로젝트에서 두 앱을 빌드해 서명을 맞춘다. Debug 빌드를 사용한다.
4. 두 기기의 위치를 켜고 정확한 위치 권한을 허용한다. 휴대폰은 인터넷을 연결한다. 휴대폰 앱에서 연결된 워치가 표시되는지 확인한다.

APK 출력:

- `wear/build/outputs/apk/debug/wear-debug.apk`
- `mobile/build/outputs/apk/debug/mobile-debug.apk`

## 1. 실내: 가상 속도 측정 (T1·T2)

- [ ] 첫 화면의 가상 걷기를 켠 뒤 내 속도에 들어가 가상 속도 안내가 표시되는지 확인한다.
- [ ] 보통 걸음·빠른 걸음·뛰기를 각각 30초 측정한다. 결과는 각각 1.1 / 1.6 / 2.8 m/s여야 한다.
- [ ] 저장 후 나갔다 들어오고 앱을 다시 실행해 값이 남는지 확인한다.
- [ ] 측정 도중 취소하고 다시 시작하면 30초부터 새로 측정하는지 확인한다.

가상 측정은 화면·T2 연결·저장 확인용이다. 센서 검증 결과와 구분해 기록한다.

## 2. 실내: 가상 경로 안내 (T3~T6)

- [ ] 목록의 목적지 이름·거리·예상 시간·내 속도 표시와 스크롤을 확인한다.
- [ ] 시연 경로를 선택하고 시·분 및 오늘/내일을 바꿔 본다. 지난 시각으로 출발할 수 없어야 한다.
- [ ] 가상 걷기로 출발해 남은 시간·거리·현재/필요 속도의 갱신을 확인한다.
- [ ] 목표 시각을 넉넉하게/빠듯하게 설정해 초록·노랑·빨강·검정 상태와 빨강 제목 강조를 확인한다. 상태 확정에 시간이 걸릴 수 있다.
- [ ] 중도 종료 결과와 실제 가상 경로 완주 결과를 각각 확인한다. 처음으로 버튼이 목적지 목록으로 돌아가야 한다.

## 3. 야외: 실제 속도 측정 (T1·T2)

- [ ] 가상 걷기를 **끔 (실제 위치)**으로 바꾼다. 내 속도 화면에 가상 속도 안내가 없어야 한다.
- [ ] 야외에서 각 종류로 30초씩 움직이며 측정한다. m/s·km/h 표시와 보통 < 빠름 < 뛰기 순서를 확인한다.
- [ ] 저장 후 앱을 종료·재실행해 실제 측정값이 유지되는지 확인한다.
- [ ] 정지 상태 등 유효한 속도가 없는 측정은 실패 안내를 표시하고 기존 저장값을 덮어쓰지 않아야 한다.
- [ ] 측정 취소·뒤로 가기·홈 이동·위치 권한 거부를 확인하고, 실패·재시도 시 앱이 종료되거나 위치 수신이 남는지 기록한다.

T2는 첫 속도 표본부터 5초와 0.4 m/s 미만을 제외한 중앙값을 사용한다. 실제 속도 정확도는 GPS 수신 상태에 따라 확인한다.

## 4. 야외: 휴대폰 검색 → 전송 → 실제 도착 (T9·T10 및 T3~T6)

- [ ] 휴대폰에서 현재 위치로부터 도보 3~5분 거리의 장소를 검색해 결과를 선택한다.
- [ ] 미래 도착 시각을 선택하고 워치로 보낸다. 위치 찾기 → 경로 받기 → 전송 성공을 확인한다.
- [ ] 워치 목록 맨 위의 📱·장소 이름을 확인한다. 선택하면 휴대폰에서 보낸 도착 시각이 반영돼야 한다.
- [ ] 가상 걷기가 꺼져 있는지 확인한 뒤 출발한다. 휴대폰 현재 위치 근처에서 시작하는 경로여야 한다.
- [ ] 실제로 걸어 남은 거리·속도 갱신 및 도착 결과 화면을 확인한다.
- [ ] 휴대폰 위치 끄기·권한 거부·인터넷 끊기·워치 연결 끊기를 각각 시험한다. 실패 안내 후 설정을 복구하면 재시도할 수 있어야 한다.

상세 실패 절차는 [T10 검증](T10-verification.md)을 참고한다.

## 기록

각 항목을 통과 / 실패 / 미확인으로 기록한다. 실패 시 직전 조작, 화면 사진, 발생 시각, 가상/실제 모드를 함께 남긴다. 실제 기기에서 확인하기 전에는 완료로 표시하지 않는다.

PC 사전 확인 명령(PowerShell):

```powershell
./gradlew.bat :wear:assembleDebug :mobile:assembleDebug :core:test :wear:testDebugUnitTest :mobile:testDebugUnitTest :mobile:lintDebug --offline
```

기존 워치 lint는 `Haptics.kt`의 API 호환성과 `MainActivity.kt`의 Fragment 버전 진단으로 실패한 이력이 있다. 해당 문제와 실제 기기 검증 결과는 별도로 기록한다.
